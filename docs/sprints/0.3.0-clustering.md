# Sprint 0.3.0 - Clustering

## Problem Statement

The project needs to group sensors by behavior so reliability users can spot similar operating patterns and outliers. This sprint adds deterministic clustering over processed sensor snapshots after the `0.2.x` trend, evidence, and feature-contract bridge has proven that those snapshots are stable, inspectable, and suitable for clustering.

## Requirements

1. Consume the dimension-specific feature matrix contract from sprint `0.2.8`.
2. Run clustering by like-for-like dimensions: X with X, Y with Y, Z with Z, and temperature with temperature.
3. Normalize features before clustering using a reusable scaler step.
4. Run KMeans with a fixed random seed and configurable cluster count.
5. Save clustered sensor rows, cluster summary statistics, clustering metrics, and optional PCA coordinates under `data/processed/clusters/`.
6. Add `sensor-data cluster run --date YYYY-MM-DD --dimension x --k 4 --source mock`.
7. Add a basic cluster drift artifact that compares cluster assignments or centroids between two processed dates for the same dimension.
8. Document how to choose `k`, choose a dimension, and where cluster outputs are written.

## In Scope

- Feature selection.
- Dimension-specific cluster runs.
- Scaling, KMeans, PCA coordinates, and cluster summaries.
- Silhouette and Calinski-Harabasz metrics where data size permits.
- CLI output for cluster runs.
- First drift comparison artifact.
- Pytest coverage over deterministic mock inputs.

## Out of Scope

- Production-grade anomaly detection.
- Interactive visual tuning of clusters.
- Model registry or persisted fitted model storage.
- Real-time clustering.
- Maximo overlay logic.
- Web visualization.

## Test Out Plan

- Run `uv run pytest` with a fixed mock snapshot and deterministic clustering settings.
- Test feature selection excludes identifier and metadata fields.
- Test output files include `cluster`, metric values, and cluster summary rows.
- Test metrics are skipped or marked unavailable when sample size is too small.
- Test drift comparison produces stable output for two known fixture snapshots.
- Test CLI command writes files into a temporary data directory.

## Next Sprint Lead In

Sprint `0.3.1` hardens the full operating pipeline around memory-conscious window processing. With clustering artifacts in place, the next step is proving that useful date ranges can flow through fetch, SQLite load, snapshots, features, clusters, trends, and drift without loading the whole range into memory.
