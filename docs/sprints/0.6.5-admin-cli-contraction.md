# Sprint 0.6.5 - Admin CLI Contraction

## Problem Statement

The CLI currently exposes 25 commands across fetch, validation, raw lifecycle,
store loading, snapshot building, trend building, five workflow variants, reports,
legacy clustering, registered clustering, Maximo diagnostics, health, and serving.

That command tree reflects the order in which internal stages were developed. It is
not the operational interface required by a web-first service. Operators primarily
need to start the service, synchronize dates, repair specific derived data, inspect
health, and export data.

This sprint contracts the public CLI while preserving internal functions and safe
recovery paths until final retirement.

## Working Decisions

### Public commands describe operator intent

The target command surface is:

```text
sensor-data serve
sensor-data sync
sensor-data rebuild
sensor-data doctor
sensor-data export
```

Internal stages remain testable Python functions. They are not all public Typer
commands.

### Source comes from service configuration

Normal commands use the configured source and data directory. Mock operation uses a
mock environment/configuration and separate data directory rather than parallel
`mock-*` command families.

### Synchronization is the normal update path

`sync` accepts one date or an inclusive range and performs the complete durable-fact
workflow:

```text
fetch -> validate -> persist -> verify -> active models -> finalize retention
```

It is idempotent and resumable from ingestion-run state.

### Rebuild is the patch path

`rebuild` operates only on already acquired or explicitly re-fetched dates. It can
target snapshots, events, active models, or all derived facts. Destructive
replacement is explicit and audited.

### Export is opt-in

CSV/JSON files are generated only through `export`, with explicit domain, range,
scope, and destination arguments.

## Requirements

1. Implement the five target command families over the `0.6.1` services and `0.6.2`
   durable write path.
2. Make `sync` support one date or an inclusive bounded range.
3. Make `sync` resume or safely retry incomplete ingestion-run states.
4. Build the active model by default after a snapshot succeeds, with an explicit
   option to defer models if needed.
5. Make `rebuild` target `snapshots`, `events`, `models`, or `all`.
6. Require explicit source re-fetch permission when retained raw evidence is absent.
7. Make `doctor` report database schema, ingestion readiness, snapshot/model gaps,
   stale models, event backfill gaps, configuration, and bounded Maximo connectivity
   diagnostics.
8. Make `export` write snapshot, trend, event, and active-model outputs without
   altering operational state.
9. Standardize human-readable output and `--json` summaries across commands.
10. Keep secrets out of logs and structured output.
11. Add deprecated aliases for necessary legacy commands during this sprint, with
    replacement instructions and no new behavior.
12. Stop registering report, raw lifecycle, store staging, trend build, mock
    workflow, and legacy clustering commands in the primary help tree.
13. Update CLI and operating documentation around web-first service administration.

## Command Sketch

```powershell
uv run sensor-data serve
uv run sensor-data sync --date 2026-07-30
uv run sensor-data sync --start-date 2026-07-24 --end-date 2026-07-30
uv run sensor-data rebuild --date 2026-07-30 --component models
uv run sensor-data doctor --start-date 2026-07-24 --end-date 2026-07-30
uv run sensor-data export trends --start-date 2026-07-24 --end-date 2026-07-30 --output exports/trends.csv
```

Exact option names may change, but separate mock/API workflow commands must not
return.

## In Scope

- Five-command public CLI.
- Idempotent synchronization and targeted rebuild.
- Operational diagnosis.
- Explicit exports.
- Deprecation aliases and documentation.
- CLI test contraction around operator outcomes.

## Out of Scope

- Task scheduling or Windows service installation.
- Browser write/admin controls.
- Remote job queues.
- Multi-tenant source selection.
- Deleting internal functions required for compatibility.
- Removing legacy stored data.

## Compatibility Gate

Every documented operational outcome from the old CLI must map to one of:

- the new public commands;
- an internal test/helper API;
- an explicitly retired development artifact with no web dependency.

Before old commands are removed in `0.6.6`, run both old and new workflows against
temporary mock stores and compare durable facts.

## Acceptance Criteria

1. Top-level help presents five operator-oriented commands.
2. One `sync` command replaces the mock/API day/trend/range workflow matrix.
3. A failed range can resume without rebuilding completed dates.
4. `rebuild --component models` repairs a model gap without re-fetching sensor data.
5. `doctor` identifies current snapshot, event, and model gaps without mutating
   state.
6. `export` reproduces required CSV data without enabling routine artifact writes.
7. Deprecated commands clearly identify their replacement.
8. CLI documentation is materially shorter and centered on web-service operation.

## Test Out Plan

- Run `uv run pytest`.
- Add CLI tests for all five commands and `--json`.
- Test interrupted and resumed synchronization.
- Test rebuild with retained raw, released raw, and explicit re-fetch.
- Test doctor on healthy, incomplete, stale-model, and event-gap stores.
- Test export path validation and stable column contracts.
- Verify secret-bearing environment values never appear in output.
- Compare old and new mock workflow durable counts before retirement.

## Next Sprint Lead In

Sprint `0.6.6` removes the compatibility scaffolding, archives or deletes redundant
artifacts through a recoverable cleanup process, and closes the reshaping phase with
