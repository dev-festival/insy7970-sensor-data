# Sprint 0.6.4 - Web Workflow Reshaping

**Status:** Reshaped after `0.6.3`; ready for execution. No `0.6.4` application
code has been implemented yet.

## Problem Statement

The browser grew one state variable and control at a time as new artifact families
landed. It still tracks source, four date values, four scope identifiers, dimension,
feature space, metric, view, search, and expansion state. Much of that state is
serialized into the URL. Sprint `0.6.3` removed browser-owned `k`, but the remaining
state still exposes backend organization more than user intent.

Snapshot Review already composes trend, cluster context, events, measurements, and
diagnostics. The standalone Cluster view currently repeats part of that workflow,
but it is retained as a distinct exploratory surface: it is the future home for
spatial browsing of cluster neighborhoods, outliers, and movement. Scope rules are
duplicated between Python and JavaScript, and missing data states still advise a
browser user to run long CLI commands.

With compact store-backed contracts and one active model policy in place, the
browser can be organized around user questions rather than backend artifact types.

## Working Decisions

### Primary user workflows

The reshaped web app has four surfaces:

1. **Review** - inspect a selected date and scope with trend context, active cluster
   context, events, measurements, and data availability.
2. **Fleet Trends** - inspect scoped metric movement over a range with bounded
   details.
3. **Cluster** - explore the active-model projection for a selected date and scope.
   This sprint stabilizes the surface and its data boundary; it does not yet build
   the future starmap interactions.
4. **Drift** - inspect available active-model drift pairs and gaps over a range.

Review keeps a compact cluster explanation in operational context. Cluster remains
separate because spatial exploration is a different user question, even though both
surfaces consume the same active-policy model authority. Drift remains a distinct
fleet-level question.

### Global state is small

Global URL-backed state is limited to:

- view;
- inclusive start and end dates;
- selected scope identity.

Review and Cluster share inspection state: snapshot date, metric, and applicable
dimension. Model version, feature-space mapping, and `k` are server-owned. Source is
configured for the service instance.

### The server owns data semantics

The browser does not re-filter returned data, resolve equipment membership, infer
model readiness, or manufacture command-line recovery instructions. It renders
canonical response states and offers web-appropriate refresh or retry actions.

### Keep chart scope contained

This sprint may simplify chart inputs and rendering calls, but replacing the custom
SVG engine is not required. A chart-library decision would be a separate measured
change.

## Requirements

1. Replace the oversized `/api/artifacts` browser bootstrap with a compact service
   context containing configured source, available dates, readiness, supported
   metrics, synchronization state, and active model information. The current
   endpoint is SQLite-backed rather than a filesystem scan, but it still returns the
   full active model and drift inventory.
2. Organize navigation around Review, Fleet Trends, Cluster, and Drift.
3. Preserve Cluster as a distinct, lazy-loaded exploratory surface over the active
   model projection. Reuse the same active cluster authority in Review without
   duplicating model-selection rules in JavaScript.
4. Remove browser source, feature-space, and `k` controls.
5. Remove source, feature-space, and `k` from browser URL state.
6. Infer the applicable active cluster feature space from the selected metric and
   dimension through the service contract for both Review and Cluster.
7. Remove JavaScript scope filtering for API responses that are already scoped.
8. Keep equipment-tree selection and search, but make scope normalization consume
   canonical tree identifiers from the service.
9. Replace CLI command hints with web states such as not synchronized, model
   pending, provider unavailable, or retry available.
10. Split the current `app.js` by responsibility only where it reduces state
    coupling: state/router, API client, navigation, and view renderers.
11. Ensure a date is selectable for Review when its snapshot is ready even if its
    model is pending.
12. Make Drift show available pairs and gaps returned by the server.
13. Preserve chronological sparse-data rendering, point-selected Snapshot dates,
    coverage, diagnostics, and bounded Maximo activation.
14. Add a visible data revision/last synchronization indicator.
15. Load Cluster projection rows only when Cluster is active; do not include them in
    bootstrap context or preload them for another view.
16. Define Drift's no-feature-control contract explicitly. The preferred contract is
    one server-composed response containing labeled pair/gap summaries for every
    active feature space, rather than silently inheriting a prior Review or Cluster
    selection.

## Proposed Browser State

```text
global:
  view
  start_date
  end_date
  scope_type
  scope_id

inspection (Review and Cluster):
  snapshot_date
  metric
  dimension

local-only:
  equipment_search
  expanded_tree_nodes
  open_detail_panels
```

## In Scope

- Browser navigation and state reduction.
- Compact bootstrap/context endpoint.
- Removal of artifact-oriented controls and recovery hints.
- Server-owned scope semantics.
- A stable, lazy-loaded Cluster exploration boundary using the existing projection.
- Limited JavaScript modularization driven by the new state boundary.
- Accessibility and responsive checks for reshaped views.

## Out of Scope

- Authentication and profiles.
- User-saved dashboards.
- Replacing the chart engine.
- Adding new analytics.
- Advanced Cluster starmap behavior such as animated movement, neighborhood links,
  trails, semantic zoom, or alternative projections.
- Editing data from the browser.
- Background scheduling.
- CLI contraction.
- Legacy data deletion.

## Compatibility Gate

The following user capabilities must remain:

- select all, asset-tree, equipment, or sensor scope;
- choose a date range and Review snapshot date;
- inspect selected metric movement and missing-data coverage;
- inspect active cluster context when ready;
- inspect Waites and bounded Maximo events;
- inspect measurements and diagnostics;
- inspect fleet trends and available drift;
- explore the selected date's active cluster projection independently of Review.

URL compatibility may translate old parameters once, but newly generated URLs use
only the reduced state model.

## Acceptance Criteria

1. The browser has no source or `k` control.
2. The URL contains no source, feature-space, or `k` parameter.
3. Review provides contextual cluster explanation, while Cluster remains a distinct
   active-model exploration surface with no source, feature-space, or `k` controls.
4. Changing scope triggers one canonical server-scoped request per active view.
5. JavaScript does not repeat equipment/sensor membership filtering over response
   rows.
6. Missing models appear as a pending/missing panel state without a CLI recipe.
7. Drift renders available pairs across a range containing model gaps.
8. Existing sparse trend, Events, Measurements, and Diagnostics behavior remains
   available.
9. Browser initialization no longer downloads the full model/drift inventory.
10. Opening Review, Fleet Trends, or Drift does not preload Cluster projection rows;
    opening Cluster triggers its canonical scoped request.

## Efficiency Guardrails

The live `0.6.3` bootstrap is 335,956 bytes because it includes 88 model rows and 84
drift rows. A measured projection containing only configured source, dates,
readiness, supported metrics, active policy, revision, and latest synchronization
state was 4,725 bytes. This is a sizing reference, not a requirement to reproduce
that exact representation.

- Measure bootstrap response bytes before and after; exclude per-model metrics and
  per-pair drift inventory from initialization.
- Measure startup request count and confirm Cluster data is lazy-loaded.
- Report total JavaScript bytes before and after. Module splitting is an ownership
  improvement and must not be claimed as a byte saving without measurement.
- Keep the `0.6.0` response budgets for active view requests.
- Expect no meaningful SQLite or raw-data disk reduction: this sprint changes the
  browser and read contracts, not stored facts or retained rollback data.
- Confirm the sprint creates no new processed data artifacts. Any disk difference
  should be limited to small static source/module changes.
