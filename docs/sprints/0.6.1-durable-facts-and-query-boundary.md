# Sprint 0.6.1 - Durable Facts and Query Boundary

## Problem Statement

The service currently decides where data lives inside a large composition module:
snapshots come from CSV, trends prefer SQLite and fall back to CSV, reference rows
merge SQLite and CSV, events prefer SQLite and fall back to raw JSON, and cluster
requests choose between file artifacts and the registered SQLite model path.

These fallbacks were useful while capabilities were landing, but they now create
multiple answers to the same request and hide incomplete migrations. They also make
it difficult to guarantee that web-visible facts survive retention.

This sprint introduces one operational query boundary over durable facts. It does
not yet remove historical writers or storage copies; it changes what the web service
trusts.

## Working Decisions

### SQLite is the operational read authority

FastAPI and the browser read operational snapshots, references, action items,
availability, and registered model facts through repository/query functions backed
by SQLite.

CSV, JSON, and raw source files remain migration inputs and explicit diagnostic
evidence. They are not silent production fallbacks.

### Missing data is explicit

A missing table, incomplete migration, or unavailable date returns a typed
availability result or a clear service error. A SQLite failure must not be swallowed
and replaced by a stale file response.

### Durable facts are distinct from staging

Durable web facts are:

- compact asset-tree, equipment, and installation-point references;
- daily sensor snapshots;
- Waites action items/events;
- ingestion run status and checksums;
- registered model runs, assignments, centroids, and drift;
- bounded Maximo results obtained on demand.

Timestamp-native readings and date-scoped copies of reference data are staging and
may be released after durable-fact verification.

### Repository functions return product-shaped records

Callers request a review context, trend series, equipment tree, event set, or model
view. They do not request paths or decide whether to parse a file.

## Requirements

1. Introduce a narrow query/repository package for:
   - service context and per-date readiness;
   - equipment and sensor hierarchy;
   - daily snapshot measurements;
   - scoped trend series and detail rows;
   - durable Waites events;
   - registered cluster and drift views.
2. Move operational SQL out of `artifact_views.py` and
   browser-specific composition helpers.
3. Keep FastAPI route handlers limited to input validation, repository calls, and
   HTTP error mapping.
4. Define typed not-found, unavailable, and corrupt-store errors.
5. Stop catching general `sqlite3.Error` and returning empty collections on
   operational reads.
6. Define a durable Waites event identity and update policy. Repeated daily source
   observations must not create misleading duplicate Events rows.
7. Persist action-item provider dates, status, asset/sensor identifiers, title,
   description, urgency, and first/last-seen information required by the web view.
8. Add a migration/backfill operation that imports retained raw action items when
   available and reports dates that require a narrow source re-fetch.
9. Query equipment-tree activity from SQLite daily snapshots rather than loading
   every daily CSV.
10. Add indexes for the actual source/date/scope predicates used by the compact
    `0.6.0` API contracts.
11. Make each operational response identify its SQLite data revision or ingestion
    completion timestamp.
12. Preserve the current CSV and artifact writers until `0.6.2` verifies read
    parity.

## Proposed Package Boundary

```text
insy_sensor_data/
  store/
    connection.py
    schema.py
    context.py
    snapshots.py
    references.py
    events.py
    models.py
  services/
    review.py
    trends.py
    drift.py
```

The exact filenames may change, but storage queries and response composition must no
longer be interleaved in one artifact-discovery module.

## In Scope

- SQLite-backed operational repositories.
- Durable Waites event contract.
- Equipment-tree and trend query migration.
- Explicit availability and storage errors.
- Backfill reporting for retained and released action-item dates.
- Route and service composition updates.

## Out of Scope

- Removing `snapshot_json` or dynamic snapshot columns.
- Stopping snapshot and model artifact writes.
- Dropping legacy tables.
- Changing clustering math.
- Browser navigation redesign.
- CLI command contraction.
- Destructive data cleanup.

## Migration and Compatibility Gate

For every API contract moved to the repository boundary:

1. run the existing implementation and capture stable semantic counts;
2. run the new SQLite query against the same data;
3. compare dates, identifiers, values, missing-value behavior, and scope counts;
4. switch the route only after parity is demonstrated;
5. return an explicit migration error if required SQLite facts are missing.

File fallback remains callable only by migration/export code. It is removed from the
normal FastAPI path.

## Acceptance Criteria

1. Normal FastAPI requests do not open snapshot, trend, feature, cluster, or
   reference CSV files.
2. Equipment-tree construction performs bounded SQLite queries and preserves current
   asset-tree/equipment/sensor labels and activity dates.
3. A SQLite read error produces a visible service error rather than an empty
   successful response.
4. Waites events survive release retention and are deduplicated according to the
   documented provider identity policy.
5. Backfill reports clearly distinguish imported, re-fetch-required, and genuinely
   empty event dates.
6. Repository tests cover source/date/scope indexes and representative missing-data
   cases.
7. The `0.6.0` response-size budgets remain satisfied.

## Test Out Plan

- Run `uv run pytest`.
- Add repository integration tests against temporary SQLite databases.
- Test corrupt, absent, partially migrated, and current schemas.
- Compare repository and legacy semantic output over mock dates.
- Test action-item status updates and repeated observations.
- Verify that released raw payloads do not cause Events to silently appear empty.
- Use SQL query plans for the main trend and equipment-tree predicates and confirm
  that intended indexes are used.

## Next Sprint Lead In

Sprint `0.6.2` changes the write path to match the new read authority: one fixed
SQLite snapshot representation, direct durable-fact ingestion, and explicit exports
instead of routine artifact mirrors.
