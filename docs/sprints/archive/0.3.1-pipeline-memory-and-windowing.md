# Archived Sprint 0.3.1 - Pipeline Memory and Windowing

Status: Archived before implementation. The memory concerns in this spec were substantially reduced by sprint `0.2.9`, which made live raw evidence and timestamp-native SQLite observations releasable after daily snapshot persistence. The active `0.3.1` spec is now [Operating Window and Cluster Interpretation](../0.3.1-operating-window-and-cluster-interpretation.md).

## Original Problem Statement

After clustering exists, the project needs to prove that a valuable operating window can be processed without loading too much raw JSON, snapshot CSV, trend data, feature data, or cluster output into memory at once. The normal path should pull narrow, persist immediately, process from daily snapshot storage and compact artifacts, and iterate by date or batch. This sprint makes memory behavior an explicit pipeline contract.

## Requirements

1. Define the supported operating-window workflow for live data, including date chunking and range-level outputs.
2. Add a range workflow or pipeline helper that processes one date at a time through fetch, validate, daily snapshot storage, feature matrix, and cluster-ready artifacts.
3. Ensure range trend and drift steps read from SQLite daily snapshots or per-date artifacts without loading the entire raw range into memory.
4. Add memory/logging summaries for each workflow step: input row counts, output row counts, elapsed time, and approximate artifact sizes where practical.
5. Add guardrails for large windows, including clear warnings or confirmation prompts when a requested range exceeds a configured threshold.
6. Define failure/resume behavior so a partially completed range can continue from existing valid artifacts.
7. Keep raw JSON as short-lived evidence only; clustering should consume feature matrices or SQLite-backed daily snapshot facts, not raw endpoint payloads or timestamp-native observation rows.
8. Add tests using small fixtures that assert the range workflow iterates by date and reuses existing artifacts.

## In Scope

- Date-window orchestration for live and mock ranges.
- Explicit per-date processing order and resume behavior.
- Memory-conscious range trend and cluster orchestration.
- Step summaries that report counts, paths, durations, and artifact sizes.
- Tests with fixture-backed small ranges.
- Documentation for the efficient pull-and-process path.

## Pipeline Contract

The efficient operating path should be:

```text
for each date in range:
    fetch raw evidence
    validate raw shape
    verify raw manifest/artifacts
    record ingestion ledger
    build daily snapshot CSV and SQLite rows
    release or retain raw/native evidence according to the retention mode
    build feature matrix preview
    run per-date clustering when requested

after date loop:
    build trend outputs from SQLite daily snapshots or compact snapshot CSVs
    compare drift from cluster artifacts
    generate report or API-ready artifacts
```

No command in this path should require holding all raw endpoint payloads for the full range in memory.

## Suggested Commands

The exact command names can settle during implementation, but the sprint should produce something close to:

```powershell
uv run sensor-data workflow api-range --start-date 2026-07-19 --end-date 2026-07-21 --facility 679
uv run sensor-data workflow mock-range --start-date 2025-07-09 --end-date 2025-07-11
```

Useful options:

```powershell
--resume
--force
--max-days N
--skip-fetch
--skip-cluster
--json
```

`--resume` should be the default posture when existing valid artifacts are present. `--force` should rerun steps deliberately.

## Step State

Each date should have an explainable step state:

```text
pending
skipped_existing
completed
warning
failed
```

The combined workflow summary should make it obvious which dates were processed, reused, skipped, or failed.

## Out of Scope

- New compression policy.
- New raw release policy beyond the retention modes defined in sprint `0.2.9`.
- Broad deletion or archiving of processed artifacts.
- Rewriting the SQLite schema unless a measured bottleneck requires it.
- Production scheduling.
- Browser UI changes.
- Maximo ingestion.

## Test Out Plan

- Run `uv run pytest`.
- Test a mock range processes dates one at a time and writes expected ledger, snapshot, feature, trend, and cluster artifacts.
- Test rerunning with default resume behavior reuses valid existing artifacts.
- Test `--force` rebuilds artifacts.
- Test large-range guardrails produce clear warnings or require confirmation.
- Test JSON workflow output includes per-date step states and counts.
- Test range trend building does not read raw JSON artifacts or timestamp-native rows when SQLite daily snapshots are available.

Sprint `0.3.2` adds packing and compression policies after the pipeline can process a window efficiently. With memory behavior explicit, packing can focus on disk footprint, verification, and retention without changing the clustering input path.
