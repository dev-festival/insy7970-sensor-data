# Sprint 0.3.2 - Artifact Packing and Retention

## Problem Statement

Once clustering and memory-conscious range processing are in place, the project needs a disciplined way to compact and retain artifacts without breaking future analysis. Raw JSON, processed CSVs, feature matrices, trend outputs, cluster outputs, reports, and manifests have different roles. This sprint defines and implements a packing lifecycle that reduces disk footprint while keeping evidence verifiable and working artifacts usable.

## Requirements

1. Define artifact tiers: raw evidence, SQLite observations, daily snapshots, trends, features, clusters, drift, and reports.
2. Add packing commands that compress eligible artifacts after the working layers needed for clustering and reporting exist.
3. Keep manifests and small metadata files readable as plain JSON unless a clear need emerges.
4. Verify packed artifacts through checksums and readable storage checks.
5. Preserve logical artifact identity so downstream loaders can read plain or packed forms where practical.
6. Add range-level packing for an operating window.
7. Add dry-run-first retention commands for old or superseded artifacts.
8. Document which artifacts are safe to pack early, which should wait until after clustering, and which should remain plain.

## In Scope

- Processed artifact compression for snapshots, trends, feature matrices, cluster CSVs, and drift CSVs.
- Raw evidence compression policy integrated with the post-clustering workflow.
- Verification metadata for packed artifacts.
- Range packing commands.
- Retention dry-runs and explicit deletion confirmation.
- Tests that prove loaders can read packed and unpacked forms where supported.
- Documentation for operator-safe retention.

## Artifact Tier Policy

Initial policy:

| Tier | Role | Packing Policy |
|---|---|---|
| Raw Waites endpoint JSON | Evidence and reprocessing source | gzip after validation and SQLite load; retain manifest plain |
| SQLite observations | Native working store | keep as SQLite; optionally vacuum/checkpoint, do not gzip active DB |
| Daily snapshots | Analyst daily facts and feature input | gzip CSV after feature and cluster artifacts exist, if loaders support it |
| Trend outputs | Range-level analyst facts | gzip CSV after report/API consumers can read packed artifacts |
| Feature matrices | Clustering input contract | keep current window plain until clustering succeeds; pack older windows |
| Cluster outputs | Modeling result artifacts | pack CSVs after report/API consumers can read packed artifacts |
| Drift outputs | Range comparison artifacts | pack CSVs after report/API consumers can read packed artifacts |
| Reports | Human evidence | keep current HTML/Markdown readable; archive older report directories separately |
| Metadata/manifests | Navigation and verification | keep plain JSON |

Packing should never be the only proof that data was processed. It should run after the necessary working artifacts exist and can be verified.

## Suggested Commands

The exact command names can settle during implementation, but the sprint should produce something close to:

```powershell
uv run sensor-data pack date --source api --date 2026-07-21
uv run sensor-data pack range --source api --start-date 2026-07-01 --end-date 2026-07-31
uv run sensor-data pack verify --source api --start-date 2026-07-01 --end-date 2026-07-31
uv run sensor-data pack prune --source api --older-than-days 90
uv run sensor-data pack prune --source api --older-than-days 90 --delete --confirm-delete
```

Useful options:

```powershell
--include raw,snapshots,trends,features,clusters,drift,reports
--dry-run
--json
```

Dry-run should be the default for pruning and any destructive operation.

## Loader Contract

Loaders should support packed artifacts before the packing commands rely on them. The project already supports raw `.json` and `.json.gz` through the artifact reader. This sprint extends that idea where useful:

- CSV readers should support `.csv` and `.csv.gz`.
- Metadata readers should continue to read plain JSON.
- API routes should not fail merely because an older processed CSV is packed.
- The current active SQLite database should remain an ordinary SQLite file.

## Out of Scope

- Cloud/object storage.
- Automated scheduled retention.
- Backups outside the configured data directory.
- Encrypting artifacts.
- Database partitioning or migration to a server database.
- Changing clustering behavior.
- Browser UI changes beyond loader compatibility.

## Test Out Plan

- Run `uv run pytest`.
- Test packing compresses eligible raw and processed artifacts while leaving metadata readable.
- Test verification catches missing files and checksum mismatches.
- Test snapshot, trend, feature, and cluster loaders can read packed CSVs where supported.
- Test pack dry-run reports intended actions without modifying files.
- Test prune refuses to delete without explicit confirmation.
- Test range packing reports counts by artifact tier.

## Next Sprint Lead In

Sprint `0.4.0` can harden API and static web surfaces on top of a pipeline that has proven clustering, memory-conscious processing, and artifact packing. The web layer should read the same verified artifacts rather than becoming a separate data path.
