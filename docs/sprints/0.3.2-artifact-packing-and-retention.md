# Deferred Sprint 0.3.2 - Artifact Packing and Retention

Status: Deferred. The raw-release and daily-snapshot work from sprint `0.2.9` reduced the immediate storage and memory pressure enough that packing is no longer the next highest-value implementation step. Keep this spec as a parking lot for later disk-footprint work, but do not treat it as the required next sprint after `0.3.1`.

## Deferral Rationale

The current operating path stores durable daily facts in SQLite and CSV, then releases bulky live raw endpoint payloads and timestamp-native observations by default. At the current tested scale, daily snapshots, feature matrices, cluster outputs, and drift outputs are small enough to keep plain and easy to inspect.

Packing adds loader complexity because every downstream reader must handle both plain and compressed forms. That complexity is worth paying when processed artifacts become large, when older operating windows accumulate, or when the dashboard/API layer needs long-lived historical windows. It is premature before cluster interpretation and dashboard surfacing mature.

## Revisit When

- Processed artifacts for real operating windows are large enough to affect developer or operator workflows.
- The dashboard/API needs older historical windows online without keeping all CSVs plain.
- Retention rules need to distinguish active windows, recent historical windows, and archived evidence.
- SQLite file maintenance, CSV compression, or report archiving becomes a measured disk-footprint problem.

## Deferred Requirements

1. Define artifact tiers: ingestion ledger, optional raw evidence, SQLite daily snapshots, daily snapshot CSVs, trends, features, clusters, drift, reports, and archive manifests.
2. Add packing commands that compress eligible processed artifacts only after the working layers needed for clustering, reporting, and dashboard loading exist.
3. Keep manifests and small metadata files readable as plain JSON unless a clear need emerges.
4. Verify packed artifacts through checksums and readable storage checks.
5. Preserve logical artifact identity so downstream loaders can read plain or packed forms where practical.
6. Add range-level packing for older operating windows.
7. Add dry-run-first retention commands for old or superseded artifacts.
8. Document which artifacts are safe to pack early, which should remain plain while active, and which should remain durable ledger records.

## Deferred Artifact Tier Policy

| Tier | Role | Future Packing Policy |
|---|---|---|
| Ingestion ledger | Durable proof of pull, validation, counts, and retention | Keep in SQLite/plain metadata; do not gzip active ledger |
| Optional raw Waites endpoint JSON | Inspection and replay source when explicitly retained | Gzip if retention mode is `compress`; release by default live workflow policy from sprint `0.2.9` |
| SQLite daily snapshots | Queryable downstream working facts | Keep as SQLite; consider vacuum/checkpoint commands before compression concepts |
| Daily snapshot CSVs | Portable analyst facts and feature input | Keep active window plain; pack older windows only after loaders support `.csv.gz` |
| Trend outputs | Range-level analyst facts | Keep active reports plain; pack older windows after API/report readers support packed CSVs |
| Feature matrices | Clustering input contract | Keep active window plain until clustering and interpretation succeed |
| Cluster outputs | Modeling result artifacts | Keep active window plain for inspection; pack older windows later |
| Drift outputs | Range comparison artifacts | Keep active window plain for inspection; pack older windows later |
| Reports | Human evidence | Keep current HTML/Markdown readable; archive older report directories separately |
| Metadata/manifests | Navigation and verification | Keep plain JSON |

Packing should never be the only proof that data was processed. The ingestion ledger and daily snapshot store remain the durable proof.

## Possible Future Commands

```powershell
uv run sensor-data pack date --source api --date 2026-07-21
uv run sensor-data pack range --source api --start-date 2026-07-01 --end-date 2026-07-31
uv run sensor-data pack verify --source api --start-date 2026-07-01 --end-date 2026-07-31
uv run sensor-data pack prune --source api --older-than-days 90
uv run sensor-data pack prune --source api --older-than-days 90 --delete --confirm-delete
```

Useful future options:

```powershell
--include raw,snapshots,trends,features,clusters,drift,reports
--dry-run
--json
```

Dry-run should be the default for pruning and any destructive operation.

## Loader Contract Before Reactivation

Loaders should support packed artifacts before packing commands rely on them:

- CSV readers should support `.csv` and `.csv.gz`.
- Metadata readers should continue to read plain JSON.
- API routes should not fail merely because an older processed CSV is packed.
- The active SQLite database should remain an ordinary SQLite file.

## Out of Scope While Deferred

- Implementing pack commands now.
- Changing clustering behavior.
- Blocking sprint `0.4.0`.
- Cloud/object storage.
- Automated scheduled retention.
- Encrypting artifacts.
- Database partitioning or migration to a server database.

## Future Test Out Plan

- Run `uv run pytest`.
- Test packing compresses eligible processed artifacts while leaving metadata readable.
- Test verification catches missing files and checksum mismatches.
- Test snapshot, trend, feature, cluster, and drift loaders can read packed CSVs where supported.
- Test pack dry-run reports intended actions without modifying files.
- Test prune refuses to delete without explicit confirmation.
- Test range packing reports counts by artifact tier.
