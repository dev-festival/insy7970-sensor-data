# Sprint 0.4.2 - Chart Rendering and UI Polish

## Problem Statement

Sprint `0.4.0` used Plotly.js to get charts on screen quickly. Sprint `0.4.1` should make navigation and parameter state coherent. After those two steps, the visual layer needs attention: charts should fit their containers, render predictably, support the exact sensor data shapes, and feel like part of a small operational tool rather than a generic plotting demo.

This sprint decides whether Plotly remains the right rendering layer or whether the app should move to a small home-grown SVG chart module tailored to snapshots, trends, clusters, and drift.

## Design Direction

Prefer a lightweight custom SVG renderer if it can cover the current chart needs without creating a fragile mini-framework. The project values plain, inspectable, dependency-light artifacts and should apply the same taste to the web layer when practical.

Plotly can remain temporarily if replacing it would slow down the sprint too much, but the output must be professionally framed and centered. A charting library is an implementation detail; chart behavior and layout are the product contract.

## Chart Contracts

### Snapshot Chart

Purpose:

```text
compare selected metric values across sensors for one date
```

Initial chart:

```text
ranked bar or dot plot by selected metric
```

Required controls:

```text
metric family
dimension when applicable
top N or all visible rows
```

### Trend Chart

Purpose:

```text
show selected sensor or equipment behavior across the global date range
```

Initial chart:

```text
line chart by date
```

Required controls:

```text
metric family
dimension
equipment/sensor scope
```

### Cluster Chart

Purpose:

```text
show all sensors in PCA space for one source/date/dimension/k
```

Initial chart:

```text
scatter plot colored by cluster
```

Required interactions:

```text
hover or selection shows sensor/equipment identity
selected equipment/sensor is visually emphasized
```

### Drift Chart

Purpose:

```text
show aligned movement across adjacent dates or a cluster window
```

Initial chart:

```text
bar chart of aligned changed ratio by date pair
```

Required details:

```text
warning state
interpretation text
raw label changes versus aligned changes
```

## Requirements

1. Fix chart sizing, centering, and responsive behavior across desktop and narrow browser widths.
2. Decide whether to keep Plotly for the current sprint or replace it with a small SVG chart module.
3. If replacing Plotly, create reusable chart helpers for axes, scales, labels, hover states, empty states, and legends.
4. If keeping Plotly, wrap it behind a narrow local chart adapter so the rest of the UI does not depend directly on Plotly calls.
5. Add metric-family controls for snapshot and trend views.
6. Add selected equipment/sensor highlighting where relevant.
7. Improve empty, loading, missing-artifact, and error states inside the chart area.
8. Ensure chart text, axis labels, legends, and table content do not overlap on supported viewport sizes.
9. Keep business logic out of the browser; browser code may aggregate for display but must not own clustering, drift, unit conversion, or feature engineering rules.
10. Remove unused chart dependency references if Plotly is replaced.

## In Scope

- Chart rendering cleanup.
- Snapshot, trend, cluster, and drift chart components/adapters.
- Metric/dimension display controls.
- Responsive layout and visual QA.
- Static smoke tests for expected chart containers and controls.
- Browser-level manual verification with local `sensor-data serve`.

## Out of Scope

- Changing clustering math.
- API-triggered cluster computation.
- Live source drilldown.
- Maximo overlay.
- Authentication or saved user profiles.
- Full design-system extraction.

## Test Out Plan

- Run `uv run pytest`.
- Add static tests for chart containers, metric controls, and removal or isolation of direct Plotly coupling.
- Manually inspect the dashboard at desktop and narrow widths.
- Verify each tab has a non-overlapping chart, a useful empty state, and a stable table.
- Verify selected equipment/sensor context is reflected in trend and cluster visuals.
- If a custom SVG renderer is introduced, test scale/domain helpers with deterministic inputs.

## Next Sprint Lead In

Sprint `0.4.3` should add deliberate on-demand cluster building after navigation and chart behavior are stable. The chart layer should be able to display either existing artifacts or newly ensured artifacts without caring how they were produced.
