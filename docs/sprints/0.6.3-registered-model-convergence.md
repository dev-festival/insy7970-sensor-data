# Sprint 0.6.3 - Registered Model Convergence

## Problem Statement

The project currently has two clustering families:

- legacy dimension-oriented feature, cluster, pair-drift, alignment, and
  cluster-window artifacts;
- the registered feature-space model and drift tables used by the current browser.

The registered path still depends on generated feature CSVs and writes CSV/JSON
model mirrors before persisting equivalent rows to SQLite. Model availability also
lags snapshot availability: a single missing date can cause an entire Drift range to
fail even when most adjacent pairs are complete.

This sprint retains one registered model pipeline, computes directly from the
operational snapshot store, and treats readiness as versioned derived data rather
than inferred artifact presence.

## Working Decisions

### One active model policy

The service owns the active model configuration:

- feature-space definitions;
- `k`;
- algorithm and seed;
- feature policy version;
- scaling policy.

These values form a model version. The browser does not choose arbitrary `k` values
or request models that were never built.

### Registered models are the only operational cluster path

Legacy dimension artifact loaders no longer serve FastAPI. Reusable mathematical
helpers may be extracted into a small engine module, but legacy file orchestration
is not retained as a second implementation.

### Feature vectors are computed from SQLite rows

Model building queries the fixed daily snapshot representation and constructs its
feature matrix in memory. No feature CSV is required as an intermediate contract.

### Readiness follows snapshot revision

A model is ready only when its input snapshot revision matches the current durable
snapshot revision. Rebuilding a snapshot marks dependent model results stale until
they are rebuilt.

### Gaps are data, not total failure

Drift over a range returns complete adjacent pairs and an explicit list of missing
or stale pairs. A gap does not discard valid results elsewhere in the range.

## Requirements

1. Extract reusable scaling, KMeans, PCA, metric, and centroid-alignment math from
   legacy artifact orchestration.
2. Define one active registered model policy in application configuration/code.
3. Build feature vectors directly from fixed SQLite snapshot fields.
4. Persist model runs, assignments, centroids, PCA coordinates required by the
   browser, metrics, and warnings transactionally in SQLite.
5. Persist drift runs and centroid alignment in SQLite without routine CSV/JSON
   mirrors.
6. Associate every model run with the exact snapshot data revision and model policy
   version.
7. Mark or detect stale model runs after snapshot rebuild.
8. Add per-date model readiness to the service context.
9. Return partial Drift windows with missing/stale pair diagnostics.
10. Default Snapshot Review cluster context to the active model for its selected
    metric/dimension.
11. Rebuild the currently missing API model dates and verify the current date range
    no longer fails solely because of gaps.
12. Stop normal registered-model code from creating feature, cluster-model, or
    cluster-model-drift artifact directories.
13. Remove legacy cluster loaders from FastAPI, while leaving their files untouched
    until `0.6.6`.

## In Scope

- Registered model engine and SQLite persistence.
- Active model policy and versioning.
- Direct snapshot-to-feature computation.
- Staleness and readiness.
- Partial drift range semantics.
- FastAPI cutover to registered models only.

## Out of Scope

- Choosing an operationally optimal `k` through new research.
- Online learning or continuous retraining.
- Forecasting, anomaly alarms, or automated maintenance decisions.
- Browser navigation redesign.
- Deleting legacy clustering files or tables.
- Replacing KMeans with another algorithm.

## Migration and Compatibility Gate

- Recompute representative mock and API dates with the store-backed engine.
- Compare deterministic assignments, centroid summaries, PCA availability, and
  drift alignment to the current registered implementation.
- Explain and approve any numerical tolerance difference before cutover.
- Preserve old registered tables/artifacts read-only until the new model revision
  passes browser and API parity.

The legacy dimension path is not required to match the active registered model; it
is being retired because it is not the operational browser contract.

## Acceptance Criteria

1. Building the active model for a date reads no feature or snapshot CSV.
2. A normal model build creates no processed model artifact directory.
3. The service exposes one active `k` and model policy version.
4. Rebuilding a daily snapshot makes its previous model visibly stale.
5. Rebuilding that model restores readiness without affecting unrelated dates.
6. Drift over a range with one missing date returns valid pairs plus an explicit gap
   instead of a 404 for the whole range.
7. Snapshot Review uses the active model without receiving browser-supplied `k`.
8. The current API snapshot dates have an auditable ready/stale/missing model status.

## Test Out Plan

- Run `uv run pytest`.
- Add deterministic engine tests with numeric tolerances.
- Compare store-backed and current registered model results on fixture dates.
- Test snapshot revision invalidation.
- Test missing first, middle, and last dates in Drift ranges.
- Test a date with insufficient feature rows.
- Verify no feature/model files are created during normal builds.
- Manually inspect Snapshot cluster context and Drift after rebuilding current gaps.
