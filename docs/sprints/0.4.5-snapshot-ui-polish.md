# Sprint 0.4.5 - Snapshot UI Polish

## Problem Statement

The Snapshot review workspace now has enough real data behind it, but the layout still behaves like an early proof of concept. The main review area grows and shrinks with the equipment navigation tree, which makes the selected equipment context and plots feel unstable. The trend and cluster plots are stacked vertically, pushing the event and measurement tables too far down the page. The lower tables are always visible, even when the reviewer only wants the visual summary.

The result is functional, but not yet comfortable for daily review.

## Working Decision

Treat the Snapshot tab as a fixed work surface with independent scroll regions:

```text
page shell
  global controls
  tab strip
  review layout
    equipment navigator pane
      search and all-equipment controls pinned
      tree scrolls independently
    snapshot workspace pane
      selected equipment metadata pinned
      chart area scrolls under metadata
      lower detail tables collapse beneath charts
```

The left equipment navigator and right snapshot workspace should not resize each other vertically after the page loads. Each pane owns its own scroll behavior.

## Layout Requirements

### Pane Behavior

The app should fit within the viewport on desktop and avoid whole-page vertical drift during normal review.

Required behavior:

1. The equipment navigator remains a left pane.
2. The equipment tree scrolls inside the navigator.
3. The snapshot workspace is a right pane with its own scroll region.
4. Expanding a long equipment tree must not push the Snapshot charts or metadata down the page.
5. The main Snapshot pane should keep a stable height derived from the viewport, not from the tree content.

Implementation target:

```text
src/insy_sensor_data/api/static/index.html
src/insy_sensor_data/api/static/styles.css
src/insy_sensor_data/api/static/app.js
```

### Pinned Snapshot Context

The selected equipment/sensor metadata must stay visible at the top of the Snapshot workspace while the lower Snapshot content scrolls.

Pinned metadata includes:

```text
equipment name
sensor name when selected
asset number
row count
sensor count
scope
```

The pinned context should be compact. It should not consume more vertical space than necessary, and it should not look like a giant card.

### Chart Layout

Trend and Cluster context should sit side by side on desktop:

```text
+----------------------+----------------------+
| Trend Context        | Cluster Context      |
| chart                | chart                |
+----------------------+----------------------+
```

Rules:

1. Use a two-column chart grid at normal desktop widths.
2. Collapse to one column on narrower screens.
3. Give both chart panels stable dimensions so loading text, SVG redraws, hover states, and status text do not shift the layout.
4. Re-render or redraw charts after any layout-changing event, including table expand/collapse if needed.
5. Keep chart containers visually quiet and utilitarian.

### Collapsible Detail Tables

Events and Measurements should be below the charts as collapsible sections.

Recommended structure:

```text
+ Events (N scoped events)
+ Measurements (N measurement rows)
```

Rules:

1. Use native `details` / `summary` where practical.
2. Preserve existing table IDs so the current render functions can keep targeting the same tables.
3. Show counts in the collapsed headers.
4. Default Measurements to collapsed.
5. Default Events to collapsed unless a future alert workflow needs it open by default.
6. Expanded table bodies should scroll internally once they exceed a practical height.

## Interaction Requirements

- Selecting a new asset tree, equipment, or sensor should update the pinned context and both charts without causing layout jumps.
- Expanding and collapsing equipment tree nodes should only affect the left navigator scroll area.
- Switching tabs should preserve normal global controls and should not leave stale Snapshot scroll positions in non-Snapshot views.
- The Snapshot pane may reset scroll to top when a new scope is selected; this is acceptable and probably desirable.
- Collapsed table state may reset on new scope selection in this sprint.

## Visual Direction

The UI should feel like a focused review tool, not a report page.

Use:

- smaller vertical padding;
- clear pane boundaries;
- subtle separators instead of heavy cards;
- compact headings;
- stable grid sizing;
- restrained color.

Avoid:

- nested card stacks;
- large blank vertical regions above charts;
- chart panels that stretch to the height of the navigator;
- table sections that dominate the first viewport;
- oversized bold headings inside compact panels.

## API / Data Requirements

No new data endpoints are required for this sprint.

The Snapshot workspace should continue using:

```text
GET /api/snapshot-review/{date}
GET /api/trends
GET /api/clusters
```

Do not change the shape of Snapshot review data unless a tiny UI convenience field materially reduces browser complexity.

## In Scope

- Snapshot workspace layout restructure.
- Independent scroll behavior for navigator and Snapshot pane.
- Sticky/pinned selected equipment metadata.
- Side-by-side Trend and Cluster panels.
- Collapsible Events and Measurements sections.
- CSS and minimal JS needed for collapsible table behavior and chart redraws.
- Static shell tests updated for the new markup.
- Browser smoke test for desktop and narrow viewport layout.

## Out of Scope

- New chart math or chart rendering engine changes.
- New cluster or trend API behavior.
- Maximo event integration beyond the current event table placeholder.
- Table filtering/search inside Snapshot details.
- User-saved panel open/closed preferences.
- Major styling changes to the equipment tree beyond what is necessary for pane behavior.

## Acceptance Criteria

1. With a long expanded equipment tree, the Snapshot metadata and charts remain in the right pane and do not move down with the tree.
2. The equipment tree scrolls independently from the Snapshot workspace.
3. The selected equipment metadata remains visible while scrolling Snapshot details.
4. Trend and Cluster context render side by side on desktop.
5. Events and Measurements render as collapsible sections beneath the charts.
6. Expanding a detail table does not resize the chart panels.
7. Snapshot, Trend, Cluster, and Drift tabs still render without JavaScript errors.
8. Existing API tests remain green.
9. `node --check src/insy_sensor_data/api/static/app.js` passes.

2. Open a Snapshot review with a deep equipment selection.
3. Expand enough tree nodes to force left-pane scrolling.
4. Confirm the right Snapshot pane does not move with the tree.
5. Scroll the Snapshot pane and confirm metadata stays pinned.
6. Confirm Trend and Cluster charts are side by side at desktop width.
7. Collapse and expand Events and Measurements and confirm charts remain stable.

## Next Sprint Lead In

After the Snapshot workspace has stable pane behavior, the next UI pass can focus on richer chart interpretation: selected sensor highlighting, metric summaries, event overlays, and clearer empty states for missing cluster models or sparse data.
