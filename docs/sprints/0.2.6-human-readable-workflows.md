# Sprint 0.2.6 - Human-Readable Workflows

## Problem Statement

The project now has a healthy set of small JSON-emitting commands, but the normal user experience is still too abstract. A maintainer can compose the pieces, but a project owner or reliability engineer cannot easily tell whether a date was fetched, loaded, processed, and trended successfully without reading raw JSON summaries. This sprint adds humane workflow wrappers over the existing core functions while preserving the composable JSON commands as the automation surface.

## Requirements

1. Add a `sensor-data workflow` command group for common operator flows.
2. Add `sensor-data workflow mock-day --date YYYY-MM-DD` to fetch mock Waites raw evidence, load SQLite observations, and build a snapshot for one date.
3. Add `sensor-data workflow mock-trend --start-date YYYY-MM-DD --end-date YYYY-MM-DD` to run the mock multi-day flow and build trend outputs.
4. Add `sensor-data workflow api-day --date YYYY-MM-DD --facility 679` for the live canary path: fetch, validate, verify, load SQLite, and build API-source snapshot artifacts.
5. Print human-readable progress and results by default, including paths, record counts, warnings, and next-step hints.
6. Support `--json` on each workflow command for scripts that want the combined structured summary.
7. Keep leaf commands unchanged: `waites fetch`, `store load-waites`, `snapshot build`, `trend build`, and `raw verify` should continue to print JSON.

## In Scope

- Workflow command group in the existing Typer CLI.
- Shared summary/narration helpers for consistent terminal output.
- Human-readable status sections for fetch, validate, verify, SQLite load, snapshot, and trend steps.
- Optional `--json` output for workflow commands.
- Tests that assert workflows call the same core path and produce expected artifacts.
- Documentation updates showing the difference between leaf commands and workflow commands.

## Output Style

The workflow output should make success obvious without requiring JSON literacy:

```text
Mock day workflow: 2025-07-09

[1/3] Fetched Waites raw evidence
      Raw directory: data/raw/waites/date=2025-07-09
      Endpoints: 6
      RMS rows: 21

[2/3] Loaded SQLite observations
      Database: data/processed/observations.sqlite
      Equipment: 6
      Installation points: 8
      Native observations: 39

[3/3] Built sensor snapshot
      Sensors: 9
      Snapshot: data/processed/snapshots/date=2025-07-09/sensor_snapshot.csv

Done.
```

The exact wording can evolve, but the output should be scannable, compact, and specific. It should not hide warnings. If validation returns `valid_with_warnings`, the workflow should show the warning count and the validation report path.

## Workflow Shapes

```powershell
uv run sensor-data workflow mock-day --date 2025-07-09
uv run sensor-data workflow mock-day --date 2025-07-09 --json

uv run sensor-data workflow mock-trend --start-date 2025-07-09 --end-date 2025-07-11
uv run sensor-data workflow mock-trend --start-date 2025-07-09 --end-date 2025-07-11 --input sqlite

uv run sensor-data workflow api-day --date 2026-07-19 --facility 679
```

## Out of Scope

- Quarto reports or charts.
- New data transformations beyond the existing fetch/load/snapshot/trend path.
- Clustering.
- Browser UI changes.
- Scheduled automation or background jobs.
- Replacing the JSON leaf commands.

## Test Out Plan

- Run `uv run pytest`.
- Test `workflow mock-day` writes raw evidence, SQLite observations, and a snapshot.
- Test `workflow mock-trend` writes snapshots and trend outputs for `2025-07-09` through `2025-07-11`.
- Test `--json` emits parseable combined summaries.
- Test default workflow output includes section labels, record counts, and output paths.
- Test validation warnings are surfaced in human-readable output.
- Test API workflow fails clearly when `WAITES_ACCESS_TOKEN` is missing.
