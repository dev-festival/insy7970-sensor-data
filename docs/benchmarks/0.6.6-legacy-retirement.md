# 0.6.6 Legacy Retirement and Release Hardening Benchmarks

Measured on Windows on 2026-08-02. Live service measurements are read-only over the
same 22-date API store used for the `0.6.4` benchmarks. Synchronization measurements
use an isolated one-day mock store. Migration, backup, restore, and compaction were
rehearsed on a disposable SQLite backup; Checkpoint B was not applied to live data.

## Code footprint

| Python source | Before 0.6.6 | 0.6.6 | Change |
|---|---:|---:|---:|
| Files | 60 | 55 | 5 net fewer |
| Lines | 23,250 | 14,370 | 8,880 fewer (38.19%) |
| Bytes | 815,026 | 499,361 | 315,665 fewer (38.73%) |

The net file count includes new safety and retirement tooling. Production legacy
modules plus obsolete tests account for most of the 12,652 deleted diff lines.
The application-owned JavaScript remains 66,265 bytes across four modules; the web
reshape is preserved rather than redesigned.

Cold interpreter import, app creation, and first health request took 0.603 seconds.
Working set rose from 25,243,648 to 65,179,648 bytes during that cold start. After
all representative reads it was 79,474,688 bytes, a further 14,295,040 bytes. Private
bytes were 52,625,408 after startup and 66,265,088 after the reads. This TestClient
method includes test/client runtime and is recorded as a new repeatable baseline,
not compared directly with the separately hosted `0.6.4` process figures.

## Disposable schema-v8 migration rehearsal

The rehearsal used SQLite backup APIs for the initial copy and pre-change backup,
restored the backup to a second database, applied only the manifest to the disposable
operational copy, and produced a separate `VACUUM INTO` result.

| Figure | Result |
|---|---:|
| Backup / restore / compacted integrity | `ok` / `ok` / `ok` |
| Protected row-count parity | preserved |
| Fixed facts in restored rollback copy | 18,436 |
| Legacy rows in restored rollback copy | 18,445 |
| Legacy tables after disposable migration | 0 |
| Database before/drop-only bytes | 244,944,896 / 244,944,896 |
| Compacted database | 162,832,384 bytes (155.29 MiB) |
| Database bytes reclaimed | 82,112,512 (78.31 MiB, 33.52%) |
| Representative Health/Context/Review/Trends/Cluster/Drift | all HTTP 200 |

If separately approved Checkpoint B reproduces these figures, historical files plus
database compaction would reclaim approximately 169,915,058 bytes (162.04 MiB), or
51.06% of the measured 332,747,442-byte processed footprint. That is a projection,
not a statement that live disk has already been reclaimed.

Clean schema 10 and simulated compatible schema 9 migration paths are covered by
tests; no post-`0.6.5` live schema-9 store was available. The live schema-8 copy is
the measured in-place rehearsal baseline.

## Reproduce

```powershell
uv run python scripts/benchmark_0_6_6.py --manifest maintenance/0.6.6-live-dry-run.json
uv run python scripts/benchmark_0_6_5.py --case one
uv run python scripts/rehearse_0_6_6.py
```

The rehearsal needs roughly five times the live database size in free temporary
space and deletes only its validated `.insy-0.6.6-rehearsal-*` directory after it
finishes.
