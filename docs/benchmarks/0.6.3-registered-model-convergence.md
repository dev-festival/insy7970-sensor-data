# 0.6.3 Registered Model Convergence Benchmarks

Measured on the local API-source SQLite store on 2026-07-31. Timings are local
application timings, not network or load-test results. Allocation tracking makes
instrumented timings deliberately slower, so wall-clock comparisons use matching
uninstrumented runs.

| Figure | Result |
|---|---:|
| API snapshot dates | 22 (`2026-07-06` through `2026-07-27`) |
| Active models built | 88/88 (22 dates × 4 feature spaces) |
| Active drift pairs built | 84/84 (21 pairs × 4 feature spaces) |
| Failed / insufficient models | 0 / 0 |

| Full rebuild peak working set | 43,974,656 bytes (41.94 MiB) |
| Full rebuild SQLite growth | 83,816,448 bytes (79.93 MiB) |

The disk figure is the side-by-side safety cost while the prior registered rows
remain available for rollback. Their removal is intentionally deferred to `0.6.6`.

## Steady-State Operations

| Operation | Time | Peak memory / allocation | SQLite growth |

| One adjacent drift pair (838 matched rows, instrumented) | 0.298 s | 2,645,530-byte Python allocation peak | 438,272 bytes |

The targeted wall run was 17.5× faster than rebuilding the full 22-date range. It
left an unrelated model and unrelated drift pair byte-for-byte timestamp-stable.
The allocation-instrumented targeted rehearsal took 41.155 seconds; that value is
not used for the wall-time comparison.

## Numerical Parity

The extracted engine was compared side by side with retained registered v1 rows for
API `x_accel`, `k=5`, model date `2026-07-26`, and drift `2026-07-25` to
`2026-07-26`:

- 838/838 installation IDs matched in both model and drift comparisons.
- Cluster labels, aligned drift assignments, centroid mappings, cluster counts,
  quality metrics, PCA coordinates/availability, warnings, and sensor counts were
  identical.
- Maximum assignment-distance, PCA, centroid, inertia, and drift-distance deltas
  were all `0.0`.

## Disk Boundary

The registered build test snapshots the processed-file inventory before and after
a normal model build and proves it is unchanged. The live build likewise wrote
only `observations.sqlite`; no routine feature/model/drift artifact directories
were created. Legacy artifacts already retained for rollback were not deleted.
