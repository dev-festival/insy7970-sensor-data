# 0.6.5 Admin CLI and Sustainment Sync Benchmarks

Measured on Windows on 2026-07-31 with isolated fixture-backed mock stores. Each
case ran in a fresh Python process using `scripts/benchmark_0_6_5.py`. These are
single-process operational measurements, not provider-network or load-test results.

The benchmark uses release retention and the active four-feature-space model policy.
The one-day and seven-day cases therefore include fetch, validation, durable daily
facts, four models per date, adjacent drift when available, verification, and
retention.

## Operator Surface

| Figure | Before | 0.6.5 | Change |
|---|---:|---:|---:|
| Exposed operator commands | 25 | 5 primary commands | 80% fewer |
| CLI operating guide | 28,399 bytes | 7,157 bytes | 74.8% smaller |

Compatibility commands remain callable but hidden for the 0.6.5 transition. The
visible surface and operating guide now describe operator intent rather than internal
pipeline stages.

## Time

| Case | Dates | Wall time | Average per date |
|---|---:|---:|---:|
| One-day synchronization | 1 | 0.698 s | 0.698 s |
| Seven-day catch-up | 7 | 8.847 s | 1.264 s |
| Already-current no-op | 0 | 12.04 ms median of 5 | n/a |

The later catch-up dates also build adjacent drift, so seven-day time is not expected
to equal seven isolated one-day runs. The no-op queried the durable cursor but did
not acquire a writer lease or create an audit row.

## Process Memory

| Case | Baseline working set | Peak working set | Peak increase |
|---|---:|---:|---:|
| One day | 35,307,520 bytes | 42,950,656 bytes | 7,643,136 bytes (7.29 MiB) |
| Seven days | 35,254,272 bytes | 47,476,736 bytes | 12,222,464 bytes (11.66 MiB) |

Seven times as many dates increased the process high-water mark by 1.60 times rather
than seven times. Work is completed one date at a time; the remaining increase is
Python/SQLite allocator high-water behavior plus the larger final model registry.
The five already-current calls produced no positive working-set delta.

## Temporary and Retained Raw Disk

| Case | Peak current-date raw bytes | Peak total raw bytes | Final raw bytes | Final raw files |
|---|---:|---:|---:|---:|
| One day | 25,095 | 25,095 | 12,282 | 2 |
| Seven days | 25,212 | 98,097 | 85,284 | 14 |

Peak raw evidence for the date currently being processed stayed effectively flat:
the seven-day figure is only 117 bytes (0.47%) above the one-day figure. Endpoint
payloads are released after every verified date. The final two small files per date
are the manifest and validation report, averaging 12,183 bytes per date; they explain
the linear retained-metadata portion of total raw bytes.

## SQLite and Processed Disk

| Case | Empty initialized DB | Final DB | Growth | Growth per date |
|---|---:|---:|---:|---:|
| One day | 442,368 bytes | 495,616 bytes | 53,248 bytes | 53,248 bytes |
| Seven days | 442,368 bytes | 1,155,072 bytes | 712,704 bytes | 101,814.86 bytes |

The multi-day figure includes four models per date and six adjacent-date drift sets,
which the isolated one-day figure does not. In both cases the processed directory
contained exactly one file: `observations.sqlite`. Synchronization created no routine
snapshot, trend, feature, cluster, drift, or report files.

The database SHA-256 was byte-identical before and after five already-current sync
calls. This verifies the no-op contract more strongly than row-count or revision
checks alone.

Timezone-correct scheduling on Windows adds the `tzdata` runtime dependency. Its
installed local footprint is 514,509 bytes across 630 small package files. This is a
runtime-environment cost, not operational data growth, and avoids fixed-offset/DST
errors in unattended date planning.

## Reproduce

```powershell
uv run python scripts/benchmark_0_6_5.py
```

The script creates isolated temporary stores inside the workspace, reports JSON, and
removes the stores after each child-process case.
